# IMPLEMENTATION_PLAN.md

## Implementation Plan: Optimized Offline-First CJK → English Subtitle Pipeline

Audience: AI coding agent / automated implementation assistant.

This document is self-contained. It explains the project context, the constraints, the final chosen approach, and the exact implementation work required. Do not assume prior conversation context.

---

# 1. Project Context

## 1.1 Project identity

Internal name: **Translation Agent**

User-facing name: **YouTube Subtitle Translator**

Platform target:

- Windows-first
- Python 3
- PySide6 / QML GUI
- CLI entry point: `translate.py`
- GUI entry point: `main.py`

Purpose:

Produce accurate, well-timed English `.srt` subtitles from either:

1. A YouTube URL using existing original-language captions.
2. A local media file using local ASR transcription.

Supported source languages:

- Chinese
- Japanese
- Korean
- English passthrough where appropriate

Target language:

- English only

---

## 1.2 Hardware baseline

The primary target hardware is:

- 8th-generation Intel i5 CPU
- 16 GB RAM
- No dedicated GPU
- CPU-only inference

All implementation decisions must respect this baseline.

Do not introduce changes that assume:

- CUDA
- VRAM
- large RAM headroom
- fast server-grade CPUs
- always-available internet

---

## 1.3 Current core local translation model

The current local translation model is:

```text
Hy-MT2-1.8B-1.25bit-v2.gguf
```

Approximate size:

```text
~440 MB
```

This is a very small, CPU-feasible translation model.

Because it is already tiny, the project strategy is **not** to replace it with a larger default model.

The strategy is:

> Keep Hy-MT2 as the default offline translation model and improve the pipeline around it.

A model replacement is only acceptable if benchmark evidence proves that the replacement is both:

1. More accurate, and
2. Faster or at least equally fast while using equal or fewer resources.

Larger models that are merely more accurate are not acceptable as the default offline path.

---

## 1.4 Current local ASR stack

Local ASR uses:

- FunASR runtime binaries
- SenseVoiceSmall GGUF
- FSMN VAD GGUF
- FFmpeg for audio extraction and silence detection

Whisper.cpp must not be reintroduced.

This is a hard project invariant.

---

# 2. Primary Goal

The goal is to produce:

> Accurate, natural, faithful, well-timed English subtitles locally on low-spec hardware, with an optional hybrid assistance path that does not become a crutch.

The offline path must be made as strong as possible.

The hybrid/cloud path must only be used:

- when explicitly enabled,
- for exceptional/failing segments,
- or when the user explicitly selects cloud translation.

---

# 3. Hard Invariants

Do not break any of the following.

## 3.1 Timestamps are sacred

For YouTube-sourced subtitles and cloud-translated output:

- Do not modify cue start times.
- Do not modify cue end times.
- Only replace cue text.

For local ASR output, timestamps are generated by the pipeline. Improvements to local ASR cue timing are allowed, but they must be deterministic and must not silently corrupt timing.

## 3.2 Cue count in == cue count out

The number of translated lines must equal the number of source cues.

Never silently:

- drop cues,
- merge cues,
- reorder cues,
- duplicate cues.

The numbered-item protocol exists to enforce this.

## 3.3 Target language is fixed to English

Do not add other target languages unless explicitly requested in a future task.

## 3.4 Foreignization philosophy must be preserved

Preserve the existing foreignization behavior.

Do not rewrite or sanitize:

- `_FOREIGNIZATION_DIRECTIVE`
- `_HY_MT2_STYLE`

unless explicitly instructed.

You may append auxiliary instructions, such as glossaries, but the core directive must remain intact.

## 3.5 No Whisper.cpp

Local ASR remains:

- FunASR
- SenseVoiceSmall
- FSMN VAD

Do not add Whisper.cpp, faster-whisper, WhisperX, or similar Whisper-based stacks.

## 3.6 Do not block the QML thread

All pipeline work must remain on background workers / `QThreadPool`.

## 3.7 Local servers accept placeholder API keys

Local llama.cpp server endpoints may use placeholder keys.

Remote endpoints must require real keys.

---

# 4. Strategic Summary

The final approach is:

## 4.1 Keep the current local translation model

Keep:

```text
Hy-MT2-1.8B-1.25bit-v2.gguf
```

## 4.4 Improve subtitle readability

- characters per second,

## 4.5 Add optional quality aids

Add:

- glossary support,

## 4.6 Add benchmarking and tests

Add:

# 10. Phase 1 — Translation Batching and Hy-MT2 Reliability

This is one of the most important phases.

The current default batch size is 40 cues per request.

For Hy-MT2 on CPU, 40 cues is too aggressive. It increases the chance of:

- missing numbered lines,
- malformed output,
- context overflow,
- slow fallback to per-item translation.

The goal is to make Hy-MT2 reliable without replacing it.

---

## 10.1 Add batching helper module

Create:

```text
src/batching.py
```

Responsibilities:

- estimate batch text size,
- split cue texts into safe batches,
- support language-aware limits,
- support model-aware limits.

### Required functions

```python
def is_cjk_language(source_language: str | None) -> bool:
    ...
```

Treat as CJK:

```text
zh
ja
ko
yue
chinese
japanese
korean
cantonese
```

Normalize language strings case-insensitively.

```python
def estimate_text_weight(text: str, source_language: str | None) -> int:
    ...
```

Purpose:

Estimate how expensive a line is for batching.

Rules:

- For CJK languages, count each non-whitespace character as weight 1.
- For non-CJK languages, count each non-whitespace character as weight 1 but allow a higher char limit later.
- Do not implement complex tokenizer estimation.
- Keep deterministic and fast.

```python
def chunk_texts(
    texts: list[str],
    *,
    max_items: int,
    max_total_chars: int,
    source_language: str | None = None,
) -> list[list[int]]:
    ...
```

Returns batches as lists of original indices.

Example:

```python
chunk_texts(["a", "b", "c"], max_items=2, max_total_chars=100)
# -> [[0, 1], [2]]
```

Rules:

- Never reorder indices.
- Never drop indices.
- Preserve original order.
- If a single item exceeds `max_total_chars`, it still becomes its own batch.
- Do not split a single cue text here. Cue text splitting is ASR's responsibility.

## 10.2 Add Hy-MT2-specific batching defaults

Modify:

```text

```

Add constants:

```python
HY_MT2_DEFAULT_MAX_BATCH_CUES = 12
HY_MT2_MAX_BATCH_CHARS_CJK = 700
HY_MT2_MAX_BATCH_CHARS_NON_CJK = 1000
```

Behavior:

If `_is_hy_mt2(model)` is true:

- Effective max batch cues = `min(requested_batch_size, HY_MT2_DEFAULT_MAX_BATCH_CUES)`.
- Use dynamic character-based batching.
- For CJK source languages, use `HY_MT2_MAX_BATCH_CHARS_CJK`.
- For non-CJK source languages, use `HY_MT2_MAX_BATCH_CHARS_NON_CJK`.

If the user explicitly requested a larger batch size, log:

```text

```

Do not treat this as an error.

For cloud models:

- Keep existing default behavior unless dynamic batching is safe and non-breaking.
- If dynamic batching is introduced for cloud models, use much larger defaults and do not reduce existing behavior aggressively.

## 10.4 Implement fallback ladder

Replace the current simplistic behavior:

```text
batch fails -> retry -> per-item fallback
```

with:

```text
batch fails
  ↓
retry batch with stricter instruction
  ↓
split batch in half
  ↓
recursively translate halves
  ↓
if halves still fail, split further until single item
  ↓
single-item fallback
```

### New helper

Add in `src/translate.py`:

```python
def _translate_group(
    client,
    model,
    texts: list[str],
    system_prompt: str | None,
    *,
    source_language: str | None,
    hy_mt2: bool,
    max_retries: int,
    depth: int = 0,
    glossary: str | None = None,
) -> list[str] | None:
    ...
```

Behavior:

1. If `texts` is empty, return `[]`.
2. If `len(texts) == 1`, use `_translate_one`.
3. Try `_translate_batch`.
4. If parse succeeds and length matches, return result.
5. If parse fails:
   - If retries remain, retry with `STRICT:` style instruction.
   - If still failing and `len(texts) > 1`, split into two halves.
   - Translate each half recursively.
   - Concatenate results in original order.
6. If all recursive attempts fail, return `None` for the group only if caller can handle group failure. For top-level translation, single-item fallback must eventually be attempted.

### Depth guard

Add a maximum recursion depth guard.

Example:

```python
MAX_SPLIT_DEPTH = 8
```

If depth exceeds guard, fall back to per-item translation for that group.

## 11.4 Add translation memory

Create:

```text
src/translation_memory.py
```

Purpose:

Reuse exact translations for repeated source lines.

This helps with:

- repeated greetings,
- opening/ending lines,
- catchphrases,
- episode previews,
- recurring terminology.

### Storage

Use SQLite.

Default location:

```text
./cache/translation_memory.sqlite3
```

Create the directory if missing.

### Schema

Table:

```sql
CREATE TABLE IF NOT EXISTS translation_memory (
    key TEXT PRIMARY KEY,
    source_language TEXT NOT NULL,
    source_text TEXT NOT NULL,
    translated_text TEXT NOT NULL,
    model_profile TEXT NOT NULL,
    glossary_hash TEXT NOT NULL,
    created_at TEXT NOT NULL,
    last_used_at TEXT NOT NULL,
    hits INTEGER NOT NULL DEFAULT 1
);
```

### Key generation

Key must be a SHA-256 hash of:

```text
source_language | model_profile | glossary_hash | normalized_source_text
```

Normalization:

- trim whitespace,
- collapse consecutive whitespace to single space,
- preserve Unicode case,
- do not remove punctuation.

`model_profile` examples:

```text
hy-mt2-local
cloud:{model_name}
```

`glossary_hash`:

- SHA-256 of formatted glossary string.
- If no glossary, use empty string hash.

### API

```python
class TranslationMemory:
    def __init__(self, db_path: str | Path):
        ...

    def get(
        self,
        *,
        source_language: str | None,
        source_text: str,
        model_profile: str,
        glossary_hash: str,
    ) -> str | None:
        ...

    def put(
        self,
        *,
        source_language: str | None,
        source_text: str,
        translated_text: str,
        model_profile: str,
        glossary_hash: str,
    ) -> None:
        ...
```

Rules:

- Use exact matching only.
- Do not use fuzzy matching.
- Do not store empty translations.
- Do not store translations that failed validation.
- Update `last_used_at` and increment `hits` on cache hit.
- Be robust against corrupt DB: if SQLite fails, log and disable TM gracefully.

## 13.4 Punctuation-aware cue splitting

Modify cue splitting function, likely:

```python
_segment_to_cues()
```

Current behavior likely splits long text proportionally.

New behavior should prefer natural boundaries.

### Splitting hierarchy

When a recognized segment is too long, split in this order:

1. Strong sentence-final punctuation:
   - `。`
   - `！`
   - `？`
   - `…`
   - `.`
   - `?`
   - `!`

2. Secondary clause punctuation:
   - `、`
   - `，`
   - `,`
   - `；`
   - `;`
   - `：`
   - `:`

3. Silence boundaries, if available.

4. Character-length proportional splitting as last resort.

### Timing assignment

Because word-level timestamps may not be available:

- Assign cue durations proportionally to subtext length.
- But boundaries should align with punctuation/silence choices.
- Do not create negative or zero durations.
- Ensure cue start/end remain within original segment start/end.
- Ensure consecutive cues are contiguous or preserve small gaps from original timing.

Example:

```text
Segment: 0.0 to 6.0
Text: "First sentence。Second sentence。"
Split into two cues.
Duration allocated by character length.
```

### Rules

- Never exceed effective max cue chars.
- Never exceed effective max cue duration unless a single sentence is longer than max duration and cannot be safely split.
- If a sentence is too long, split at clause punctuation.
- If still too long, split proportionally.
- Do not drop text.
- Do not reorder text.

The pipeline already uses:

- FunASR VAD

Enhance `_segment_to_cues` to accept optional silence boundaries inside the segment.

If silence boundaries exist:

- Prefer splitting near silence.
- Prefer splits that also coincide with punctuation.
- Avoid splitting in the middle of a word if language information suggests word boundaries, but do not implement complex tokenization.

### `chunk_texts`

```python
def chunk_texts(
    texts: list[str],
    *,
    max_items: int,
    max_total_chars: int,
    source_language: str | None = None,
) -> list[list[int]]:
```

Rules:

- Return list of index batches.
- Preserve order.
- `max_items <= 0` raises `ValueError`.
- `max_total_chars <= 0` raises `ValueError`.
- Each batch must contain at most `max_items`.
- Each batch total non-whitespace char count should not exceed `max_total_chars` unless a single item exceeds the limit.

Implementation sketch:

```python
batches = []
current = []
current_chars = 0

for idx, text in enumerate(texts):
    item_chars = len("".join(text.split()))
    if current and (
        len(current) >= max_items or
        current_chars + item_chars > max_total_chars
    ):
        batches.append(current)
        current = []
        current_chars = 0
    current.append(idx)
    current_chars += item_chars

if current:
    batches.append(current)

return batches
```

# 27. Performance Expectations

Do not optimize blindly.

Expected effects:

1. Smaller Hy-MT2 batches may increase request count but reduce failures.
2. Fewer failures should reduce expensive per-item fallbacks.
3. Translation memory should speed up repeated content.
4. Shorter ASR cues may increase cue count but improve translation reliability.
5. Local server warmup may slightly increase startup time but improve first-batch stability.

If a change improves apparent quality but significantly slows throughput, benchmark it before keeping it.

---

# 28. Benchmark Decision Rules

Do not swap models based on intuition.

A new model may replace Hy-MT2 only if all of the following are true:

1. It produces better or equal translation quality on project benchmark cases.
2. It preserves numbered-output reliability at least as well as Hy-MT2.
3. It is faster or equal in total translation time on target CPU.
4. It uses equal or less peak RAM.
5. It uses equal or less model storage.
6. It does not require GPU.
7. It does not require Whisper.cpp.
8. It works in the existing llama.cpp-compatible local server workflow.

If a model is more accurate but slower/larger, it may only be considered as an optional non-default mode, and only if explicitly requested.

# 32. Final Notes for the Implementing Agent

The purpose of this work is not to chase the largest possible model.

The purpose is to build a robust, offline-first subtitle translation pipeline that:

- respects low-spec hardware,
- preserves cue alignment,
- preserves source culture and tone,
- produces readable English subtitles,
- uses cloud assistance only as a controlled fallback.

The current Hy-MT2 model is small but viable if the pipeline around it is disciplined.

The highest-value improvements are:

1. Smarter batching.
2. Better fallback behavior.
3. Better ASR cue segmentation.
4. Better quality diagnostics.
5. Better consistency via glossary and translation memory.
6. Evidence-based benchmarking.

Implement carefully. Preserve invariants. Prefer correctness over cleverness.
