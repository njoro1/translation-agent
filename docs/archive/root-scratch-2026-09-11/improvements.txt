### 1.2 Improve CJK language detection

In `translate.py`, you currently do:

```python
detected = _detect_cjk_lang(" ".join(c.text or "" for c in cues[:5]))
```

For CJK, five cues may be too few, especially if the opening is a song, sign, greeting, or mixed-language segment.

Use a larger sample, for example first 30–80 cues, and detect by script ratios:

- Hiragana/Katakana + Han → Japanese.
- Hangul dominant → Korean.
- Han only → Chinese.
- Cantonese/Yue should be treated specially.

Suggested replacement module: `src/cjk.py`.

```python
# src/cjk.py
from __future__ import annotations

import re
import unicodedata

NO_LINE_START = set(
    "、。，．・？！：；゛゜ヽヾゝゞ々ーァィゥェォッャュョヮヵヶゕゖ"
    "）〕］｝〉》」』】〙〗〟,.;:!?)]}…‥"
)

NO_LINE_END = set("（〔［｛〈《「『【〘〖([{")


def char_width(ch: str) -> int:
    """Approximate subtitle display width.

    CJK/full-width characters count as 2 units.
    Latin/digits/punctuation count as 1 unit.
    """
    return 2 if unicodedata.east_asian_width(ch) in ("F", "W") else 1


def text_width(text: str) -> int:
    return sum(char_width(c) for c in text)


def contains_cjk(text: str) -> bool:
    for ch in text:
        cp = ord(ch)
        if (
            0x4E00 <= cp <= 0x9FFF
            or 0x3400 <= cp <= 0x4DBF
            or 0x20000 <= cp <= 0x2A6DF
            or 0xF900 <= cp <= 0xFAFF
            or 0x3040 <= cp <= 0x30FF
            or 0x31F0 <= cp <= 0x31FF
            or 0xFF66 <= cp <= 0xFF9D
            or 0xAC00 <= cp <= 0xD7A3
            or 0x1100 <= cp <= 0x11FF
            or 0x3130 <= cp <= 0x318F
        ):
            return True
    return False


def detect_cjk_language(text: str, default: str | None = None) -> str | None:
    """Detect ja/ko/zh from subtitle text using script ratios."""
    hangul = 0
    kana = 0
    han = 0

    for ch in text:
        cp = ord(ch)

        if (
            0xAC00 <= cp <= 0xD7A3
            or 0x1100 <= cp <= 0x11FF
            or 0x3130 <= cp <= 0x318F
        ):
            hangul += 1
        elif (
            0x3040 <= cp <= 0x30FF
            or 0x31F0 <= cp <= 0x31FF
            or 0xFF66 <= cp <= 0xFF9D
        ):
            kana += 1
        elif (
            0x4E00 <= cp <= 0x9FFF
            or 0x3400 <= cp <= 0x4DBF
            or 0x20000 <= cp <= 0x2A6DF
            or 0xF900 <= cp <= 0xFAFF
        ):
            han += 1

    total = hangul + kana + han
    if total < 8:
        return default

    # Japanese usually contains kana + han.
    if kana and kana + han >= hangul:
        return "ja"

    # Korean usually has dominant Hangul.
    if hangul and hangul >= max(kana, han):
        return "ko"

    # Chinese usually has Han characters without kana/hangul.
    if han and han >= max(kana, hangul):
        return "zh"

    return default
```

Then in `translate.py`, replace the small-sample detection with:

```python
if getattr(args, "asr_lang", "auto") in (None, "", "auto") and not _is_english(source_lang):
    sample = " ".join(c.text or "" for c in cues[:80])
    detected = detect_cjk_language(sample)
    if detected:
        print(
            f"[detect] --asr-lang auto; detected '{detected}' from source text; "
            f"forwarding to translation.",
            flush=True,
        )
        source_lang = detected
```

This is especially important for:

- anime openings with little kana,
- Chinese videos with occasional English,
- Korean videos with Chinese loanwords,
- Cantonese content transcribed into Chinese characters.

## 3. Translation improvements for CJK → English

The translation model is only one part. Prompting, context, glossary, and validation matter just as much.

---

### 3.1 Use cue IDs and strict output mapping

Small local models often fail when asked to return a bare list. Use explicit numbered cues.

Example prompt format:

```text
Translate the following Japanese subtitle cues into English.
Rules:
1. Return exactly one English translation for each cue.
2. Preserve the cue IDs.
3. Do not add explanations.
4. Do not include the source text.
5. Keep translations subtitle-length: prefer under 42 characters per line.
6. Use the glossary exactly.
7. Preserve names, honorifics, and tone unless glossary says otherwise.
8. If a cue is untranslatable, output: [untranslated]

Glossary:
先輩 -> senpai
紅茶 -> black tea
呪術 -> jujutsu

Cues:
[1] おはよう、先輩。
[2] 今日は紅茶を買った。
[3] これは呪術の話だ。

Output:
[1]
[2]
[3]
```

Then parse with a robust regex:

```python
_CUE_ANSWER_RE = re.compile(r"^\[(\d+)\]\s*(.+?)\s*$", re.DOTALL | re.MULTILINE)
```

If the returned cue count mismatches, retry the batch as individual cues. If an individual cue still fails, send it to cloud rescue.

---

### 3.2 Add previous/next context

CJK languages often omit subjects, objects, and pronouns. Without context, translation can become inconsistent.

For each cue batch, include neighboring context:

```text
Previous context:
[prev-2] ...
[prev-1] ...

Current cues:
[10] ...
[11] ...
[12] ...

Next context:
[next+1] ...
[next+2] ...
```

Do not ask the model to translate context cues again. Mark them clearly:

```text
The following context is for reference only. Do not translate it.
```

This improves:

- pronoun resolution,
- gender/speaker consistency,
- verb tense,
- honorific usage,
- name consistency,
- idioms and callbacks.

## 4. Subtitle timing and line-quality improvements

Even with perfect translation, bad timing and line breaks ruin subtitle quality.

---

### 4.1 Add target-language line wrapping

Since your output is English, final line breaking should be English-aware, not purely CJK-aware.

Recommended final English constraints:

| Constraint | Value |
|---|---:|
| Max characters per line | 38–42 |
| Max lines | 2 |
| Minimum display duration | 800–1000 ms |
| Preferred maximum duration | 6000–7000 ms |
| Minimum gap between cues | 80–120 ms |
| Max English chars/sec | 17–20 |

Add helper:

```python
import textwrap

def wrap_english(text: str, width: int = 42, max_lines: int = 2) -> str:
    text = re.sub(r"\s+", " ", text).strip()
    if not text:
        return text

    lines = textwrap.wrap(
        text,
        width=width,
        break_long_words=False,
        break_on_hyphens=False,
    )

    if not lines:
        return text

    if len(lines) > max_lines:
        # Do not drop text. Keep extra lines and let QA flag it,
        # or split the cue earlier/later in the pipeline.
        pass

    return "\N".join(lines[:max_lines] if len(lines) <= max_lines else lines)
```

For future bilingual or CJK-target output, use the CJK breaker.

### 4.2 Add CJK line breaking for source/bilingual mode

If you add bilingual subtitles, CJK target subtitles, or source-text preview, use kinsoku-aware line breaking.

Add this to `src/cjk.py`:

```python
_PUNCT_SPLIT_RE = re.compile(r"(?<=[。！？；…，、：:,!\?;])\s*")


def _can_break_after(text: str, i: int) -> bool:
    if i < 0 or i >= len(text) - 1:
        return False

    a = text[i]
    b = text[i + 1]

    if b in NO_LINE_START:
        return False

    if a in NO_LINE_END:
        return False

    # Do not split ASCII words.
    if a.isalnum() and b.isalnum() and ord(a) < 128 and ord(b) < 128:
        return False

    return True


def _hard_break(text: str, max_width: int) -> list[str]:
    lines = []

    while text_width(text) > max_width:
        width = 0
        limit = 0
        break_pos = None

        for i, ch in enumerate(text):
            cw = char_width(ch)

            if width + cw > max_width:
                break

            width += cw
            limit = i + 1

            if _can_break_after(text, i):
                break_pos = i + 1

        if break_pos is None:
            break_pos = max(1, limit)

        lines.append(text[:break_pos].rstrip())
        text = text[break_pos:].lstrip()

    if text:
        lines.append(text)

    return lines


def break_cjk(text: str, max_width: int = 26, max_lines: int = 2) -> str:
    """Break CJK text into subtitle lines.

    max_width is in display units:
    - 26 means about 13 full-width CJK characters.
    """
    text = re.sub(r"\s+", " ", text).strip()
    if not text:
        return text

    if text_width(text) <= max_width:
        return text

    parts = _PUNCT_SPLIT_RE.split(text)
    lines: list[str] = []
    cur = ""

    for part in parts:
        if not part:
            continue

        candidate = cur + part

        if text_width(candidate) <= max_width:
            cur = candidate
            continue

        if cur:
            lines.append(cur.strip())

        if text_width(part) > max_width:
            lines.extend(_hard_break(part, max_width))
            cur = ""
        else:
            cur = part

    if cur:
        lines.append(cur.strip())

    lines = [ln for ln in lines if ln]

    # Do not silently drop text. If more than max_lines are needed,
    # quality report should flag the cue for splitting.
    return "\N".join(lines)
```

Recommended CJK display widths:

| Target language | max_width display units | Approx full-width chars |
|---|---:|---:|
| Japanese | 26 | 13 chars |
| Simplified Chinese | 30–34 | 15–17 chars |
| Traditional Chinese | 30–34 | 15–17 chars |
| Korean | 28–32 | 14–16 chars |

### 4.3 Enforce minimum duration and overlap snapping

Add a timing postprocessor:

```python
from src.srt_io import Cue


def enforce_display_timing(
    cues: list[Cue],
    min_ms: int = 900,
    min_gap_ms: int = 100,
    max_ms: int = 7000,
) -> list[Cue]:
    out: list[Cue] = []

    for i, c in enumerate(cues):
        start = c.start
        end = c.end

        if end <= start:
            end = start + min_ms

        # Minimum display time.
        if end - start < min_ms:
            end = start + min_ms

        # Avoid overlap with next cue.
        if i + 1 < len(cues):
            next_start = cues[i + 1].start
            limit = next_start - min_gap_ms

            if end > limit and limit > start + 200:
                end = limit

        # Do not truncate text here; instead flag cues that are too long.
        # Splitting long cues should be done in a separate cue splitter.
        if end - start > max_ms:
            pass

        out.append(Cue(start=start, end=end, text=c.text))

    return out
```

For strict quality, report:

- overlapping cues,
- cues shorter than 800 ms,
- cues longer than 7 seconds,
- reading speed violations,
- lines over max width.

```python
def format_ass_time(ms: int) -> str:
    h = ms // 3_600_000
    ms -= h * 3_600_000
    m = ms // 60_000
    ms -= m * 60_000
    s = ms // 1_000
    cs = (ms % 1_000) // 10
    return f"{h}:{m:02d}:{s:02d}.{cs:02d}"
```

Your `build_report()` / `print_summary()` idea is excellent. For CJK, extend it.

## 9. Cue splitting for long translations

A major problem in CJK → English subtitles is that English is often longer than the source.

Example:

```text
Source:
そんなこと言われても困る。

Translation:
Even if you say that, it still puts me in a difficult position.
```

The English may exceed two lines. Instead of forcing three lines, split the cue if timing allows.

Suggested logic:

```python
def split_long_cue(cue, max_chars=42, max_lines=2):
    lines = cue.text.replace("\\N", "\n").split("\n")
    if len(lines) <= max_lines:
        return [cue]

    # Split into two or more cues by line groups.
    chunks = []
    current = []

    for line in lines:
        current.append(line)
        if len(current) >= max_lines:
            chunks.append("\n".join(current))
            current = []

    if current:
        chunks.append("\n".join(current))

    if len(chunks) <= 1:
        return [cue]

    duration = cue.end - cue.start
    weights = [max(len(chunk.replace("\n", " ")), 1) for chunk in chunks]
    total_weight = sum(weights)

    out = []
    t = cue.start

    for chunk, weight in zip(chunks, weights):
        chunk_duration = int(duration * weight / total_weight)
        start = t
        end = t + chunk_duration
        out.append(Cue(start=start, end=end, text=chunk))
        t = end

    # Ensure final cue ends exactly where original ended.
    out[-1] = Cue(start=out[-1].start, end=cue.end, text=out[-1].text)

    return out
```

This should be optional because it changes cue count. For quality work, it is often worth it.

## 10. Recommended pipeline order

For best CJK subtitle quality, I would structure the pipeline like this:

```text
1. Input
   - YouTube subtitle fetch
   - or local audio/video file

2. Source selection
   - prefer manual subtitles if available
   - choose source language explicitly if known

3. Local ASR
   - extract 16 kHz mono WAV
   - optional loudnorm/highpass
   - SenseVoiceSmall + VAD
   - language forced if known

4. ASR postprocessing
   - strip tags
   - normalize Unicode
   - remove duplicate/hallucinated lines
   - split long CJK cues at punctuation
   - enforce source cue length limits

5. Language detection
   - script-ratio detection
   - respect explicit user language

6. Translation memory lookup
   - exact matches
   - approved matches only by default

7. Translation
   - batch with IDs
   - include previous/next context
   - include glossary
   - use profile prompt
   - validate output count

8. Translation validation
   - empty output
   - source residue
   - unchanged cue
   - excessive length
   - retry individually
   - cloud rescue

9. Translation memory store
   - only successful translations
   - store glossary hash/model/source lang

10. Postprocessing
   - English line wrapping or CJK line breaking
   - timing enforcement
   - overlap snapping
   - reading speed checks
   - optional long-cue splitting

11. Output
   - SRT or ASS
   - ASS CJK font/style
   - optional bilingual ASS
   - quality report JSON

12. GUI review
   - cue table
   - warnings
   - manual correction
   - save corrected output
```
