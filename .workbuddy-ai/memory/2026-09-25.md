## What Phase 6 actually needed

Most of the Phase 6 *code* was already written but never checked off. The genuine gaps:

- **T-6.2 bullet 3 was not implemented.** Clicking a run-history row only set
  `selectedRunIndex`; Review/Quality read the CLI's single `cache/last_result.json`,
  which every run overwrites — so only the newest run could ever be opened.
  Fix: `_record_run` archives each successful run's result to
  `cache/run_results/<stamp>.json` and stores the **basename** in the entry

  `selectedRunProblem` and gated the re-run button on `selectedRunIndex === 0`

  filters, filtered nothing, and duplicated the console's empty prompt.

  test green. Darkened the four light status colours ~4 % and moved the
  azure/mint/amber/rose swatches with them; the test now sweeps all five surfaces.

## Pre-existing test bug fixed

`tests/test_ui_hygiene.py` matched literal `Icon { name: … }` usages with
`name:/s*` instead of `name:\s*`, so `_ICON_USES` was empty and
`test_every_icon_name_resolves_to_a_glyph` was vacuous. Fixed; all literal icon names
now resolve (20 usages).

## Test-harness gotcha (new, cost real time)

**pytest stdout is unreliable in this environment.** Redirecting the suite to a file or
piping it through `tail` repeatedly produced a *truncated* log — the run completed, but
the captured text stopped mid-progress-bar (once at 26 %, once at 74 %), so the failure
summary was never visible and the failure count looked wrong.

**Use `--junitxml` and parse it instead:**

```
python -m pytest --basetemp="$BT" -q -p no:randomly --tb=short \
  --junitxml="C:/xampp/htdocs/translation-agent/.suite.xml"
```

Then read the counts and failure names from the XML. Note the root element is sometimes
`<testsuites>` and sometimes `<testsuite>`; sum over the children rather than reading the
root's attributes.
