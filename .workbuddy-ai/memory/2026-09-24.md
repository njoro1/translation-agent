### Grounded the review against the actual tree first

Reading the source changed the shape of three phases. Findings worth keeping:

- **RC-1 (the real desync mechanism).** `currentIndex: { ...appBridge.X... }` on a
  `ComboBox` is a *declarative binding*, and `ComboBox` assigns `currentIndex`
  internally on activation — which destroys the binding. So from the second
  interaction onward the widget stops mirroring the store. Same class of bug for
  `editText:` on editable combos. 11 sites (5 in SettingsPage, 4 in RunPage,
  PresetPicker, CommandBar). The store already exists (`AppBridge` + notify
  signals), so Phase 0 is **binding hygiene**, not "build a store".
- **RC-2 duplicates** are genuine and enumerated by file:line in the plan.
- **RC-4.** `saveWindowState` (`bridge.py:3481`) is a plain method but `Main.qml:108`
  calls it from `onClosing` — window geometry never persists. Needs `@Slot(str)`.
- **Already-fixed review items** (verify, don't rebuild): the Quality micro-gauge
  abbreviations are *not* in `qualityTiles` (`bridge.py:3966` emits full words) —
  they are produced by `StatTile.qml:56` `label.toUpperCase()` + `elide` in a narrow
  tile. `Never persisted to disk` is already inline on the API key
  (`SettingsPage.qml:402`). The Gate card is already header-switch/body-pill. The
  Commands palette already has 24 real commands.
- **SIZE column collision source:** `modelsInventory` builds
  `size = f"{size} · {os.path.join(*tail)}"` — that is the `242.4 MB · dist\gg`
  bleed over PURPOSE.
- **Cache row wrong verb source:** the `tm` row has `action: "tm"`, which has no
  branch in `SettingsPage.qml:822-832`, so it falls through to `Download`.

### Decisions recorded

- Store stays on `AppBridge`; no new QML singleton (a singleton cannot read the
  `appBridge` context property, per `Theme.qml`'s own header comment).
- New `BoundComboBox` / `BoundField` wrappers re-apply the store value on notify.
- `readinessRows` gains a real fifth state: `ok`/`todo`/`na`/`unchecked` + an
  `actionable` flag, so `n/a` and `unchecked` stop sharing one glyph.
- Autosave replaces the `Save` button; `dirty` + 400 ms debounce + toast.
- Shortcuts become a real remap editor (persisted `ui/shortcuts` JSON).
- Appendix B items (XAMPP htdocs, API-key non-persistence, `assets/` not bundled)
  are explicitly out of scope for the UI phases.

### Four real defects the new tests found (all fixed)

- **RC-1 was not fully migrated.** `YouTubeVideoPanel.qml` codec + resolution
  pickers still bound `currentIndex: Math.max(0, indexOfValue(appBridge.…))`.
  Both are `BoundComboBox` now. A static guard in `test_ui_bindings.py` fails on
  any `currentIndex:`/`editText:` binding that reads `appBridge`.
- **`engineLocalDisabledReason` was inverted *and* unreachable.** It tested the
  current *pair*, but `pipelineMode` can only hold one of the three supported
  combinations, so `youtube + local` was never the current state and the reason
  never rendered. It now tests the **source** axis. `SegmentedControl` gained
  `disabledIds` so the impossible option is muted and inert.
- **The SOURCE card jumped 40 px between modes.** `StackLayout` sizes to the
  **current child, not the max of its children** — the in-code comment claiming
  otherwise was wrong. Fix: a `reservedHeight` high-water mark on the
  StackLayout, plus moving the YouTube-only `VIDEO DOWNLOAD (OPTIONAL)` header
  and the engine reason **inside** the body with no `visible:` guard (as
  siblings they added 28 px + 12 px spacing in YouTube mode only). Measured
  after: constant 590 px, headers share `y = 0`.
- **`ComboBox.currentIndex` off-by-one class of bug**: `applyStoreValue()` now
  compares `String(model value) === String(store value)`, so a model holding
  `720` matches a store holding `"720"`.

### Layout assertions need a shown window

Offscreen Qt never polishes an invisible window: every `height` is 0 and every
child of a non-current page reports `visible == False`. `tests/conftest.py` has
a `qml_shown` fixture that sets `width/height/visible`, sets `currentPage`, and
pumps the event loop — **and stubs `_persist_fields` to a no-op**, because
showing the window lets the 400 ms autosave debounce fire and rewrite the
developer's real `QSettings`.

## Phase 4 (visual language) + the first half of Phase 5

### The test-invocation mystery is solved

`--basetemp` must point at a **fresh, unique, pre-created** directory:

```bash
BT="C:/Users/Njoro/AppData/Local/Temp/ta_$(date +%s)"; mkdir -p "$BT"
python -m pytest tests/x.py --basetemp="$BT" -q -p no:randomly
```

A **reused** basetemp makes pytest try to delete the existing tree at session
start; the sandbox's `sitecustomize` safe-delete shim fails with
`OSError [Errno 53] The network path was not found` and pytest reports a bogus
`error` for whichever test happens to be setting up. That is what produced the
"30 errors" / "28 errors" rows in the earlier per-file sweep and, most likely,
the "full-suite run dies at ~70 %" symptom. With a fresh basetemp every file
reports clean (e.g. `test_ux_bridge.py` went 45 passed + 1 error → **46 passed**).

### `OverflowRow` froze the whole event loop — silent, no warning

`QGuiApplication.processEvents()` never returned once the Quality page was laid
out, with **no QML warning at all**. Cause: `OverflowRow` published
`implicitWidth: flow.implicitWidth` while its children's widths come from
`cellWidth`, which comes from its own `width`. A parent `Layout` then derives the
assigned width from a preferred width that is a function of the assigned width —
a cycle that never settles. Removed the `implicitWidth` binding; all five pages
lay out again.

Diagnosis recipe that worked (worth reusing): `pytest -o faulthandler_timeout=45`
shows only *that* it is stuck inside `processEvents`; the actual page is found
with a throwaway test that sweeps `root.setProperty("currentPage", 0..4)` and
appends to a **file** (not stdout — pytest's output is lost when the run is
killed). Verdict: page 2 (Quality).

**Rule:** a wrap-layout wrapper must never publish an implicit size derived from
children whose size depends on its own size.

### Contrast: `accentInk` was the real defect, not `textMuted`

`tests/test_theme_contrast.py` (new, 22 tests) parses the token table out of
`Theme.qml` and computes WCAG 2.1 ratios. Four families failed:

| token | was | now | why |
|---|---|---|---|
| `textMuted` dark | `#6E7891` | `#828DA6` | 3.60 on `surfaceRaised`, needed 4.5 |
| `textMuted` light | `#7C8698` | `#5E6779` | 3.13 on `surfaceRaised` |
| `success` light | `#12945C` | `#0F7F4C` | 3.59 as text |
| `warning` light | `#B26A00` | `#A16000` | 3.92 as text |
| `borderSoft` | `#1B2130`/`#E7EBF3` | `#212938`/`#E1E6F0` | 1.13 / 1.19 — invisible |
| **`accentInk`** | `#FFFFFF` | `isDark ? "#0A0C11" : "#FFFFFF"` | white on dark mint = **1.88** |
| `iris` dark | `#7C5CFF` | `#8A6BFF` | sat at exactly 4.50 against the new ink |

The dark-theme accents are bright pastels, so a fixed white label was illegible
on four of the five. The `mint`/`amber` accent swatches moved with
`success`/`warning` so the palette does not fork.

### Density was only half-wired

`Theme.comfortable` grew the type scale and the control heights but **not** the
spacing scale, so "Comfortable" packed bigger glyphs into identical gaps and read
*tighter* than Compact. `sm`…`xxl` are now density-aware; `xs` stays at 4 px
because it is used for hairline gaps inside a single control.

### New components and behaviours

- `OverflowRow.qml` — a `Flow` wrapper that wraps instead of clipping, exposing
  `cellWidth` derived from `minCellWidth`.
- `MetricChip.qml` — label-first metric tile (wraps, keeps natural case, reveals
  a per-metric breakdown on click). Backed by a new
  `QualityIssuesModel.breakdown(severity)` that groups the same rows the Issues
  table renders.
- `EmptyState.qml` — the *Log* pattern (icon, title, body, exactly one action).
  `QualityPage`'s whole content column and `ReviewPage`'s whole split view are now
  `visible: appBridge.resultReady`.
- `Timeline` is interactive: click a bar to select that cue, drag to filter the
  table to a cue-number range (`CueFilterProxyModel.setCueRange`).
- `CuePreviewTable`: severity moved off the row fill onto a 3 px left bar; read
  mode is a wrapping `Text` (a `TextInput` is single-line, which is why
  translations clipped); the redundant "Only problems" switch is gone.
- `setCueText` now re-runs the quality checks live, so the issue chips and the
  Quality counts move as an edit lands, and the strict-gate verdict follows.
